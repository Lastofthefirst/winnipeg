# i18n Design — English / French

**Date:** 2026-04-19
**Status:** Approved

---

## Overview

Add English/French language switching to the Bahá'í Community of Winnipeg site. Both locales are pre-built as static HTML at compile time. A language switcher in the top nav bar lets users toggle between `/en/...` and `/fr/...` URLs. Quotes and scripture remain hardcoded English. The system is designed so a future CMS can slot in client-side without touching the i18n layer.

---

## 1. URL & Routing Architecture

All production pages move one level deeper into `src/app/[locale]/`. `generateStaticParams` returns `['en', 'fr']` on every layout and page, causing the static export to pre-build both full site copies.

```
/                    → static redirect to /en
/en                  → English home
/en/about
/en/community-life
/en/learn-more
/en/events
/en/news
/en/contact
/fr                  → French home
/fr/about
/fr/community-life
... etc.
```

Trial/showcase pages (`/trial`, `/trial-community`, `/showcase`) are excluded from i18n — English only, no `[locale]` wrapping.

The root `src/app/page.tsx` becomes a static redirect to `/en` (the `x-default` locale). No server-side browser-language detection — the language switcher and direct URLs handle navigation.

## 2. Translation System

### Directory structure

```
src/
  i18n/
    config.ts           — locales array, defaultLocale
    types.ts            — Locale type, Dictionary interface (fully typed)
    getDictionary.ts    — single abstraction point for all string loading
    getCmsField.ts      — helper for locale-aware CMS field selection
    dictionaries/
      en.ts             — all English UI strings
      fr.ts             — all French UI strings
```

### The `getDictionary` abstraction

```typescript
// i18n/getDictionary.ts
import type { Locale, Dictionary } from './types'

export async function getDictionary(locale: Locale): Promise<Dictionary> {
  return (await import(`./dictionaries/${locale}`)).default
}
```

This is the only function that knows where strings come from. All pages call it once at the top. When a CMS is added in future, only this function changes — no page or component code is touched.

### Dictionary structure

Strings are organised by page and section:

```typescript
interface Dictionary {
  common: {
    getInTouch: string
    learnMore: string
    seeAll: string
    reachOut: string
    // ...
  }
  nav: {
    home: string
    about: string
    communityLife: string
    learnMore: string
    events: string
    news: string
    contact: string
  }
  meta: {
    home: { title: string; description: string }
    about: { title: string; description: string }
    communityLife: { title: string; description: string }
    learnMore: { title: string; description: string }
    events: { title: string; description: string }
    news: { title: string; description: string }
    contact: { title: string; description: string }
  }
  home: {
    hero: { eyebrow: string; heading: string; subheading: string }
    activities: { eyebrow: string; heading: string; intro: string; ... }
    community: { eyebrow: string; heading: string; body: string[]; link: string }
    events: { heading: string; intro: string }
    news: { heading: string; intro: string; link: string }
    quote: { author: string }
  }
  about: { ... }
  communityLife: { ... }
  learnMore: { ... }
  events: {
    heading: string
    intro: string
    invitation: {
      eyebrow: string
      heading: string
      body: string
      link: string
    }
    evergreenNote: string
  }
  contact: { ... }
  contactSection: { heading: string; button: string }
}
```

### Component pattern

Components never import from `i18n` directly. They accept strings as props. Pages call `getDictionary` and pass strings down:

```tsx
// page.tsx (Server Component)
export default async function AboutPage({ params }: { params: { locale: Locale } }) {
  const t = await getDictionary(params.locale)
  return (
    <PageIntro eyebrow={t.about.eyebrow} title={t.about.heading}>
      <p>{t.about.intro}</p>
    </PageIntro>
  )
}
```

This means all shared components (`PageIntro`, `SectionIntro`, `Quote`, `EventsPreview`, `ContactSection`, etc.) remain locale-agnostic — they work identically with CMS content.

## 3. Quotes & Scripture

Quotes are hardcoded English. They are not part of the dictionary and not translated. The `Quote` component receives its `children` and `author` as before — these are static JSX strings in the page files.

If quote attribution text surrounding a quote needs translation (e.g. a label like "As Bahá'u'lláh wrote:"), that label goes in the dictionary. The quote text itself does not.

## 4. Language Switcher

A client component placed in the top nav bar beside the Contact button.

```tsx
'use client'
import { usePathname } from 'next/navigation'
import Link from 'next/link'
import type { Locale } from '@/i18n/types'

export function LocaleSwitcher({ locale }: { locale: Locale }) {
  const pathname = usePathname()
  const other = locale === 'en' ? 'fr' : 'en'
  const href = pathname.replace(`/${locale}`, `/${other}`)
  return (
    <Link href={href}>
      {other.toUpperCase()}
    </Link>
  )
}
```

- Displays the *other* locale as the link label (you click `FR` to switch to French)
- No JS required to navigate — it is a plain link
- The root layout receives `locale` from `params` and passes it to the nav

## 5. SEO

### `hreflang` alternates

Every page's `generateMetadata` emits alternates:

```typescript
export async function generateMetadata({ params }: Props) {
  const t = await getDictionary(params.locale)
  const base = 'https://winnipegbahais.org'
  const path = '/about' // per page
  return {
    title: t.meta.about.title,
    description: t.meta.about.description,
    alternates: {
      canonical: `${base}/${params.locale}${path}`,
      languages: {
        en: `${base}/en${path}`,
        fr: `${base}/fr${path}`,
        'x-default': `${base}/en${path}`,
      },
    },
  }
}
```

### `<html lang>`

Set on the root layout from `params.locale`:

```tsx
<html lang={params.locale}>
```

### Root redirect

`src/app/page.tsx` redirects to `/en`. This is the `x-default` canonical. No browser-language sniffing.

## 6. CMS Integration Seam

The CMS is entirely separate from the i18n system. CMS content has separate EN/FR fields (e.g. `title_en`, `title_fr`). A single helper picks the right field at runtime on the client:

```typescript
// i18n/getCmsField.ts
export function getCmsField(
  item: Record<string, unknown>,
  field: string,
  locale: Locale
): string {
  return (item[`${field}_${locale}`] ?? item[`${field}_en`]) as string
}
```

CMS content is fetched client-side on page load. The locale comes from `useParams()`. The dictionary system is not involved.

## 7. Scope of Changes

### Structural (mechanical, per-file)
- Move all pages from `src/app/*/page.tsx` to `src/app/[locale]/*/page.tsx`
- Add `generateStaticParams` to `src/app/[locale]/layout.tsx` and each page
- Add `params: { locale: Locale }` prop to every page component
- Update all `generateMetadata` functions

### New files
- `src/i18n/config.ts`
- `src/i18n/types.ts`
- `src/i18n/getDictionary.ts`
- `src/i18n/getCmsField.ts`
- `src/i18n/dictionaries/en.ts` (~400 strings)
- `src/i18n/dictionaries/fr.ts` (~400 strings, French translations)
- `src/components/LocaleSwitcher.tsx`
- `src/app/page.tsx` → static redirect to `/en`

### Modified shared components
Components that currently contain hardcoded strings will have those strings replaced with props. No component changes its interface beyond accepting string props it previously hardcoded.

### Excluded from i18n
- `src/app/trial/`, `src/app/trial-community/`, `src/app/showcase/`
- External news feed content (Bahá'í World News Service)
- All scripture and quote text
- Author names (Bahá'u'lláh, 'Abdu'l-Bahá, The Báb)

---

## 8. Out of Scope

- Middleware-based locale detection (requires server runtime)
- Right-to-left layout support
- More than two locales
- CMS integration (deferred — seam is designed, implementation is a separate project)
- ISR / dropping `output: 'export'` (deferred to CMS phase)
